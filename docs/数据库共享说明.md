# 数据库共享说明

## 🎯 核心问题

**问题**：为什么开发人员给的账号密码无法登录？

**答案**：因为数据库是本地的，不共享！

---

## 📊 当前数据库架构

### SQLite - 本地文件数据库

```
开发人员 A 的电脑
├── backend/
│   └── hotel_management.sqlite  ← A 的数据
│       ├── 用户：wayne / xxx
│       └── 酒店：A 创建的酒店

你的电脑（开发人员 B）
├── backend/
│   └── hotel_management.sqlite  ← B 的数据（独立）
│       ├── 用户：merchant / merchant123
│       ├── 用户：admin / admin123
│       └── 酒店：B 创建的酒店

开发人员 C 的电脑
├── backend/
│   └── hotel_management.sqlite  ← C 的数据（独立）
│       └── 用户：C 创建的用户
```

**特点**：
- ✅ 每个人的数据库文件完全独立
- ❌ 数据不会自动同步
- ❌ 不会提交到 Git（在 .gitignore 中）

## 🔄 数据共享方案对比

### 方案 1：本地 SQLite（当前方案）

**适用场景**：
- ✅ 个人学习
- ✅ 独立开发
- ✅ 原型开发

**优点**：
- ✅ 零配置，开箱即用
- ✅ 轻量级，性能好
- ✅ 数据独立，互不干扰

**缺点**：
- ❌ 数据不共享
- ❌ 需要手动同步数据库文件

**当前可用账号**：
```
商户：merchant / merchant123
管理员：admin / admin123
```

---

### 方案 2：共享数据库文件

**适用场景**：
- 临时需要查看别人的数据
- 小团队简单协作

**操作步骤**：

#### 步骤 1：导出数据库（发送方）
```bash
# 开发人员 A 的操作
cd hotel-management/backend
# 将 hotel_management.sqlite 文件发送给你
# 可以通过微信、邮件、网盘等方式
```

#### 步骤 2：导入数据库（接收方）
```bash
# 你的操作
cd hotel-management/backend

# 备份当前数据库
copy hotel_management.sqlite hotel_management.sqlite.backup

# 用收到的文件替换
# 将收到的 hotel_management.sqlite 复制到这里

# 重启后端服务
# Ctrl+C 停止当前服务，然后重新启动
npm run start:dev
```

#### 步骤 3：验证
现在可以用开发人员提供的账号密码登录了！

**优点**：
- ✅ 简单快速
- ✅ 无需配置服务器

**缺点**：
- ❌ 需要手动同步
- ❌ 容易产生数据冲突
- ❌ 不适合频繁协作

---

### 方案 3：PostgreSQL 共享数据库（推荐团队协作）

**适用场景**：
- ✅ 团队协作开发
- ✅ 测试环境
- ✅ 生产环境

**架构图**：
```
┌─────────────────┐
│  开发人员 A      │
│  localhost:3000 │───┐
└─────────────────┘   │
                      │
┌─────────────────┐   │    ┌──────────────────────┐
│  开发人员 B      │   ├───▶│  PostgreSQL 服务器   │
│  localhost:3000 │───┤    │  192.168.1.100:5432 │
└─────────────────┘   │    │  共享数据库          │
                      │    └──────────────────────┘
┌─────────────────┐   │
│  开发人员 C      │   │
│  localhost:3000 │───┘
└─────────────────┘

所有人连接同一个数据库！
```

#### 实施步骤

##### 步骤 1：搭建 PostgreSQL 服务器

**选项 A：本地搭建**
```bash
# 在一台电脑上安装 PostgreSQL
# Windows: https://www.postgresql.org/download/windows/
# 安装后创建数据库
psql -U postgres
CREATE DATABASE hotel_management;
```

**选项 B：使用云数据库**
- 阿里云 RDS：https://www.aliyun.com/product/rds
- 腾讯云数据库：https://cloud.tencent.com/product/cdb
- AWS RDS：https://aws.amazon.com/rds/

##### 步骤 2：修改配置文件

所有开发人员修改 `.env` 文件：

```env
# 注释掉 SQLite 配置
# DB_TYPE=sqlite
# DB_DATABASE=hotel_management.sqlite

# 启用 PostgreSQL 配置
DB_TYPE=postgres
DB_HOST=192.168.1.100        # PostgreSQL 服务器 IP
DB_PORT=5432
DB_USERNAME=postgres
DB_PASSWORD=your_password    # 数据库密码
DB_DATABASE=hotel_management
```

##### 步骤 3：安装 PostgreSQL 驱动（如果还没安装）

```bash
cd hotel-management/backend
npm install pg
```

##### 步骤 4：重启后端服务

```bash
npm run start:dev
```

##### 步骤 5：验证

- 后端会自动连接到共享数据库
- 所有人看到的数据是一样的
- 一个人创建的用户，其他人也能看到

**优点**：
- ✅ 数据实时同步
- ✅ 适合团队协作
- ✅ 更接近生产环境
- ✅ 支持并发访问

**缺点**：
- ❌ 需要搭建服务器
- ❌ 需要网络连接
- ❌ 配置相对复杂

## 🔧 切换数据库类型

### 从 SQLite 切换到 PostgreSQL

#### 1. 修改 `.env` 文件

```env
# 改为 PostgreSQL
DB_TYPE=postgres
DB_HOST=localhost  # 或服务器 IP
DB_PORT=5432
DB_USERNAME=postgres
DB_PASSWORD=your_password
DB_DATABASE=hotel_management
```

#### 2. 重启后端

```bash
npm run start:dev
```

#### 3. 数据迁移（可选）

如果需要将 SQLite 的数据迁移到 PostgreSQL：

**方法 1：使用工具**
- pgLoader：https://pgloader.io/
- SQLite to PostgreSQL 转换工具

**方法 2：手动导出导入**
```bash
# 导出 SQLite 数据
sqlite3 hotel_management.sqlite .dump > data.sql

# 导入到 PostgreSQL
psql -U postgres -d hotel_management -f data.sql
```

**方法 3：重新创建数据**
- 后端会自动创建表结构
- 重新注册用户
- 重新创建酒店数据

## 📝 Git 和数据库

### ⚠️ 数据库文件不应该提交到 Git

查看 `.gitignore`：
```
# SQLite database
*.sqlite
```

**原因**：
- 数据库文件是二进制文件
- 包含敏感数据（用户密码等）
- 每个开发者应该有自己的测试数据
- 避免冲突

**应该提交的**：
- ✅ 代码文件
- ✅ 配置文件模板（.env.example）
- ✅ 数据库迁移脚本（如果有）

**不应该提交的**：
- ❌ 数据库文件（.sqlite）
- ❌ 环境配置（.env）
- ❌ node_modules
- ❌ 敏感信息

## 📞 常见问题

### Q2：如何获取开发人员的数据？
**A**：让他发送 `hotel_management.sqlite` 文件给你，然后替换你的文件。

### Q3：如何实现数据共享？
**A**：切换到 PostgreSQL 共享数据库。

### Q4：数据库文件在哪里？
**A**：`hotel-management/backend/hotel_management.sqlite`

### Q5：如何备份数据？
**A**：复制 `hotel_management.sqlite` 文件即可。

### Q6：如何重置数据库？
**A**：删除 `hotel_management.sqlite` 文件，重启后端会自动创建新的空数据库。
