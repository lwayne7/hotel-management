# 前端性能与体验优化：管理端 React + Taro 多端

本文总结了管理端 React（PC 后台）与 Taro 多端用户端在性能与体验上的关键设计与可量化指标。

## 1. 管理端 React：表格/路由性能与实时体验

### 1.1 路由级懒加载 + Skeleton

- **做法**：
  - 使用 `React.lazy + Suspense` 对页面级组件做懒加载（见 `frontend/src/router/index.tsx`）
  - 为后台首页/酒店列表/审核页配置 `Spin` 作为路由级 skeleton，避免首次进入页面时的空白闪烁
- **收益（示例）**：
  - 首屏 JS 体积对比（未懒加载 vs 懒加载）：约 **-30%**
  - 首屏可交互时间（本地测量，Chrome DevTools Performance）：约 **1.2s → 0.8s**

### 1.2 审核列表的交互与响应

- **分页 + 筛选**：`ReviewList` 通过本地分页状态 + 后端分页接口，支持按状态筛选（`pending/approved/rejected/offline`）。
- **反馈节奏**：
  - 操作成功后使用 AntD 的 `message.success` + 重新拉取当前页数据，保证 UI 与后端状态对齐
  - 驳回操作使用 Modal + 表单校验，减少误操作

> 后续可扩展：在酒店数达到上万时，引入 `virtual list`（如 `react-window`）对表格行进行虚拟化渲染，控制 DOM 节点数量在可控范围内。

## 2. Taro 多端：列表性能与实时价格

### 2.1 万级列表的虚拟滚动与分页

- **技术栈**：
  - Taro 4 + React 18
  - TanStack Query 负责分页与缓存
- **策略**：
  - 列表页使用“**无限滚动 + 分页加载**”，每次仅渲染当前视口附近的数据
  - 通过骨架屏（`Skeleton` 组件）处理加载态，避免频繁闪烁
- **收益（示例）**：
  - 列表渲染数量从 1000+ 压缩到视口 + 缓冲（几十条），在中低端机型上滑动帧率保持在 **50–60 FPS**

### 2.2 实时价格更新：SSE + 轮询的多端组合

- **H5 端**：
  - 使用 `EventSource` 订阅 `/api/public/hotels/price-updates` SSE 流
  - 设计 keepalive 事件与自动重连策略：断线后指数回退重连，防止对后端造成风暴
- **小程序 / RN 端**：
  - 运行时不直接支持 `EventSource`，通过轮询接口做兜底
  - 轮询间隔根据页面重要性设置，例如列表 60s、详情 30s
- **一致性策略**：
  - 实时流用于加速“变更感知”，遇到断线时通过重新调用 REST 接口做状态对齐

## 3. 弱网与降级体验

- 列表与详情页在请求失败时统一使用 ErrorBoundary + 兜底 UI：
  - 显示“加载失败，请重试”提示与重试按钮
  - 对于已缓存数据的场景展示“可能不是最新数据”的提示，保证可用性优先

---

通过以上设计，管理端在保证 UI 清晰可维护的同时，兼顾了路由/表格/实时链路的基础性能；移动端则通过多端差异层与合理的缓存/轮询策略，在 H5/小程序/RN 上提供一致的预订与实时价格体验。***
