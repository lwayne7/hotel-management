# 易宿酒店预订平台答辩 PPT 大纲（10页内）

## 第1页：项目背景与目标（30s）
- 主题：智慧出行场景下的酒店信息交互平台。
- 目标：打通“商户录入 -> 管理员审核 -> 用户预订浏览”双端闭环。
- 评分映射：功能完成度总览。

## 第2页：整体架构（50s）
- 双端一后端：移动端 `hotel-mobile-taro`、管理端 `hotel-management/frontend`、后端 `hotel-management/backend`。
- 核心链路：鉴权与角色控制、酒店状态机、公开酒店查询接口。
- 评分映射：技术复杂度、代码质量。

## 第3页：需求覆盖结果（60s）
- 展示 `docs/defense/requirement-matrix.md` 截图。
- 按三块讲：移动端三页、管理端三页、规则与状态流转。
- 明确状态口径：已完成 / 部分完成 / 待优化。

## 第4页：移动端体验亮点（60s）
- 首页：Banner、关键词、日历、标签筛选。
- 列表页：上滑加载、虚拟滚动、筛选组合。
- 详情页：轮播、房型价格升序、地图与分享可预期反馈。
- 评分映射：用户体验 + 功能完成度。

## 第5页：管理端业务闭环（70s）
- 商户：注册登录、酒店录入编辑、提交审核。
- 管理员：通过/驳回/下线/恢复。
- 重点规则：已发布/已下线酒店编辑后回到待审核；驳回原因可见。
- 评分映射：功能完成度。

## 第6页：实时与性能设计（70s）
- 实时：SSE 事件统一字段 `type/timestamp/hotelId/changeKind/version`。
- 刷新策略：按 `hotelId` 增量刷新，必要时全量刷新。
- 性能：分页 + 虚拟滚动，避免长列表全量渲染。
- 评分映射：技术复杂度 + 用户体验。
