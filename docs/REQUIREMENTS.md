# 易宿酒店预订平台 - 需求规格说明书

## 1. 项目概述

### 1.1 项目背景
随着旅游业的蓬勃发展，酒店预订成为旅行中不可或缺的一环。本项目旨在开发一个酒店预订平台，为商家提供酒店信息管理功能，为管理员提供酒店审核与发布功能。

### 1.2 项目目标
- **用户端（移动端）**：为终端用户提供酒店查询、列表、详情等预定流程页面（入口 `/explore`，无需登录）。
- **管理端（PC）**：为酒店商户提供酒店信息管理、为平台管理员提供审核与发布；构建安全、稳定、易用的管理系统。

### 1.3 用户角色
| 角色 | 描述 |
|------|------|
| 商户 (Merchant) | 酒店经营者，负责录入和管理自己的酒店信息 |
| 管理员 (Admin) | 平台运营人员，负责审核酒店信息、上下线管理 |

## 2. 功能需求

### 2.0 用户端预定流程（移动端）

用户端为**独立项目**（与 hotel-management 同级，如 `hotel-mobile`），与后端公开 API 对接。

- **酒店查询页（首页）**：顶部 Banner（酒店广告，点击跳转详情）、当前地点/关键字/入住日期（日历组件）、筛选（星级等）、快捷标签、查询按钮，点击后跳转列表页。
- **酒店列表页**：顶部筛选（城市、入住/离店、间夜、搜索）、详细筛选区域、酒店列表；列表支持**上滑自动加载**；列表项展示酒店名/星级/地址/价格等。
- **酒店详情页**：顶部导航（酒店名称、返回列表）、大图 Banner 左右滚动、酒店基础信息（名/星级/设施/地址）、日历+入住间夜 Banner、房型价格列表（**价格从低到高排序**）。
- 数据来源：仅展示状态为「已发布」的酒店；接口为公开 API（`/api/public/hotels`、`/api/public/hotels/:id`），无需登录。

### 2.1 用户认证模块（管理端）

#### 2.1.1 用户注册
- **功能描述**：新用户可以注册成为商户或管理员账号（注册时可选角色）
- **输入字段**：
  - 用户名（必填，6-20位，唯一）
  - 密码（必填，8-20位，包含数字和字母）
  - 确认密码（必填，需与密码一致）
  - 角色（必填，merchant/admin）
  - 昵称（选填）
  - 手机号（选填）
- **业务规则**：
  - 用户名不可重复
  - 密码需加密存储
  - 登录页无需选择角色，由账号自动识别并进入对应页面

#### 2.1.2 用户登录
- **功能描述**：已注册用户可通过用户名密码登录系统
- **输入字段**：
  - 用户名
  - 密码
- **业务规则**：
  - 登录成功返回 JWT Token
  - Token 有效期为 7 天
  - 前端存储 Token 于 localStorage

#### 2.1.3 Token 验证
- **功能描述**：系统验证用户身份和权限
- **业务规则**：
  - 请求头携带 `Authorization: Bearer <token>`
  - Token 过期需重新登录
  - 根据用户角色控制访问权限

### 2.2 商户功能模块

#### 2.2.1 酒店列表查看
- **功能描述**：商户查看自己创建的所有酒店
- **展示信息**：
  - 酒店名称（中/英文）
  - 酒店地址
  - 星级
  - 状态（草稿/待审核/已通过/已驳回/已下线）
  - 创建时间
  - 更新时间
- **筛选条件**：
  - 按状态筛选
- **分页**：每页 10 条，支持翻页

#### 2.2.2 新增酒店
- **功能描述**：商户创建新的酒店信息
- **酒店基本信息**：
  | 字段 | 类型 | 必填 | 描述 |
  |------|------|------|------|
  | nameCn | 字符串 | 是 | 酒店中文名称（最多100字） |
  | nameEn | 字符串 | 否 | 酒店英文名称（最多100字） |
  | address | 字符串 | 是 | 酒店地址（最多255字） |
  | starRating | 整数 | 是 | 酒店星级（1-5） |
  | openingDate | 日期 | 是 | 开业时间 |
  | description | 文本 | 否 | 酒店介绍 |
  | facilities | 数组 | 否 | 酒店设施（如：游泳池、健身房等） |
  | nearbyAttractions | 数组 | 否 | 附近景点 |
  | transportation | 数组 | 否 | 交通信息 |

- **房型信息**（可添加多个）：
  | 字段 | 类型 | 必填 | 描述 |
  |------|------|------|------|
  | name | 字符串 | 是 | 房型名称 |
  | price | 数字 | 是 | 房间价格 |
  | originalPrice | 数字 | 否 | 原价 |
  | discountType | 枚举 | 否 | 折扣类型（none/percentage/fixed/package） |
  | discountValue | 数字 | 否 | 折扣值 |
  | discountDescription | 字符串 | 否 | 折扣描述 |
  | maxGuests | 整数 | 否 | 最大入住人数 |
  | bedType | 字符串 | 否 | 床型 |
  | roomSize | 整数 | 否 | 房间面积（平方米） |
  | amenities | 数组 | 否 | 房间设施 |

- **酒店图片**（可添加多个）：
  | 字段 | 类型 | 必填 | 描述 |
  |------|------|------|------|
  | imageUrl | 字符串 | 是 | 图片URL |
  | sortOrder | 整数 | 否 | 排序顺序 |
  | description | 字符串 | 否 | 图片描述 |

- **业务规则**：
  - 新建酒店默认状态为"草稿"
  - 商户只能看到和管理自己的酒店

#### 2.2.3 编辑酒店
- **功能描述**：商户修改已创建的酒店信息
- **业务规则**：
  - "待审核"状态不可编辑（只读）
  - "草稿"、"已驳回"可编辑，保存后保持原状态（提交审核后进入待审核）
  - "已通过"、"已下线"可编辑，但保存后自动转为"待审核"，需管理员重新审核

#### 2.2.4 删除酒店
- **功能描述**：商户删除酒店记录
- **业务规则**：
  - 只有"草稿"状态的酒店可删除
  - 删除后数据不可恢复
  - 需二次确认

#### 2.2.5 提交审核
- **功能描述**：商户将酒店提交给管理员审核
- **前置条件**：
  - 酒店状态为"草稿"或"已驳回"
  - 至少添加一个房型
- **业务规则**：
  - 提交后状态变更为"待审核"
  - 清空之前的驳回原因

---

### 2.3 管理员功能模块

#### 2.3.1 酒店审核列表
- **功能描述**：管理员查看所有待审核及其他状态的酒店
- **展示信息**：
  - 酒店基本信息
  - 商户信息
  - 提交时间
  - 当前状态
- **筛选条件**：
  - 按状态筛选（全部/待审核/已通过/已驳回/已下线）
- **分页**：每页 10 条

#### 2.3.2 酒店详情查看
- **功能描述**：管理员查看酒店完整信息
- **展示内容**：
  - 酒店基本信息
  - 所有房型信息
  - 酒店图片
  - 商户信息
  - 审核历史

#### 2.3.3 审核通过
- **功能描述**：管理员审核通过酒店
- **前置条件**：酒店状态为"待审核"
- **业务规则**：
  - 状态变更为"已通过"（即已发布）
  - 记录审核时间

#### 2.3.4 审核驳回
- **功能描述**：管理员驳回酒店申请
- **前置条件**：酒店状态为"待审核"
- **输入字段**：
  - 驳回原因（必填）
- **业务规则**：
  - 状态变更为"已驳回"
  - 驳回原因对商户可见

#### 2.3.5 酒店下线
- **功能描述**：管理员将已发布酒店下线
- **前置条件**：酒店状态为"已通过"
- **业务规则**：
  - 状态变更为"已下线"
  - 下线后用户端不可见

#### 2.3.6 酒店上线
- **功能描述**：管理员将已下线酒店重新上线
- **前置条件**：酒店状态为"已下线"
- **业务规则**：
  - 状态变更为"已通过"

## 4. 酒店状态流转

```
                    ┌─────────────────────────────────────────┐
                    │                                         │
                    ▼                                         │
┌─────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐  │
│  草稿   │───▶│  待审核  │───▶│  已通过  │◀──▶│  已下线  │  │
│ (DRAFT) │    │(PENDING) │    │(APPROVED)│    │(OFFLINE) │  │
└─────────┘    └──────────┘    └──────────┘    └──────────┘  │
     ▲              │                                        │
     │              ▼                                        │
     │         ┌──────────┐                                  │
     └─────────│  已驳回  │──────────────────────────────────┘
               │(REJECTED)│
               └──────────┘
```

### 状态说明
| 状态 | 值 | 描述 | 商户可操作 | 管理员可操作 |
|------|-----|------|-----------|-------------|
| 草稿 | draft | 新建或编辑中 | 编辑、删除、提交审核 | - |
| 待审核 | pending | 等待管理员审核 | - | 通过、驳回 |
| 已通过 | approved | 审核通过，已发布 | 编辑（编辑后转待审核） | 下线 |
| 已驳回 | rejected | 审核未通过 | 编辑、提交审核 | - |
| 已下线 | offline | 管理员下线 | 编辑（编辑后转待审核） | 上线 |

## 5. API 接口规范

### 5.1 认证接口
| 方法 | 路径 | 描述 | 权限 |
|------|------|------|------|
| POST | /api/auth/register | 用户注册 | 公开 |
| POST | /api/auth/login | 用户登录 | 公开 |
| GET | /api/auth/profile | 获取当前用户信息 | 登录用户 |

### 5.2 商户接口
| 方法 | 路径 | 描述 | 权限 |
|------|------|------|------|
| GET | /api/hotels | 获取我的酒店列表 | 商户 |
| GET | /api/hotels/:id | 获取酒店详情 | 商户 |
| POST | /api/hotels | 创建酒店 | 商户 |
| PATCH | /api/hotels/:id | 更新酒店 | 商户 |
| DELETE | /api/hotels/:id | 删除酒店 | 商户 |
| POST | /api/hotels/:id/submit | 提交审核 | 商户 |

### 5.3 管理员接口
| 方法 | 路径 | 描述 | 权限 |
|------|------|------|------|
| GET | /api/admin/hotels | 获取所有酒店列表 | 管理员 |
| GET | /api/admin/hotels/:id | 获取酒店详情 | 管理员 |
| POST | /api/admin/hotels/:id/approve | 审核通过 | 管理员 |
| POST | /api/admin/hotels/:id/reject | 审核驳回 | 管理员 |
| POST | /api/admin/hotels/:id/offline | 酒店下线 | 管理员 |
| POST | /api/admin/hotels/:id/online | 酒店上线 | 管理员 |

## 6. 非功能需求

### 6.1 性能需求
- 页面加载时间 < 3 秒
- API 响应时间 < 500ms
- 支持 100 并发用户

### 6.2 安全需求
- 密码使用 bcrypt 加密存储
- JWT Token 签名验证
- 基于角色的访问控制 (RBAC)
- 防止 SQL 注入攻击
- 防止 XSS 攻击

### 6.3 可用性需求
- 表单校验提示清晰
- 操作有加载状态
- 错误信息友好提示
- 支持中文界面

### 6.4 兼容性需求
- 支持 Chrome、Firefox、Safari、Edge 最新版本
- 最低分辨率 1280x720
